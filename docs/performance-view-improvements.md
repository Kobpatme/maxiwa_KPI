# Performance View — ผลการปรับปรุงตามแผน 6 ขั้น

วันที่ดำเนินการ: 19 พฤศจิกายน 2026

## ผลลัพธ์ที่ส่งมอบ

1. **นิยามและความถูกต้อง** — ใช้สูตรคะแนนถ่วงน้ำหนักต่อชิ้นงานเดิม แสดงสูตรพร้อมตัวตั้ง/ตัวหาร งานค้างไม่รวมงานยกเลิก กรณีไม่มีคะแนนแสดงว่ายังประเมินไม่ได้ เรียง Active Weight ตามสัดส่วนที่แสดง และแยกลำดับแถวออกจากอันดับคะแนน
2. **รายละเอียดรายบุคคล** — Main KPI → Sub KPI แสดงน้ำหนักพื้นฐานปัจจุบัน น้ำหนักเฉพาะบุคคล และชุดน้ำหนักที่บันทึกกับงาน แสดง KPI ที่ได้รับมอบหมายแต่ยังไม่มีงาน และงานที่ไม่ตรงกับทะเบียนปัจจุบัน ไม่บวกน้ำหนัก Main ซ้ำตามจำนวน Sub/งาน
3. **ทะเบียนน้ำหนัก** — แยกมุมตั้งค่าปัจจุบันกับงานในช่วงที่เลือก รวมรายการที่ไม่มีงาน เลือกบุคคลเพื่อตรวจ override ไม่แทนค่าน้ำหนักงานเก่าด้วยค่าปัจจุบัน หากไม่มีทะเบียนบุคลากร ไม่อ้างว่าทราบการมอบหมาย/น้ำหนักเฉพาะคน
4. **การติดตามต่อ** — เปิดทีม บุคคล KPI และรายการงานภายใต้ขอบเขตเดิม เปิด Overdue, SLA Fail, Aging และคุณภาพข้อมูลได้ Watchlist ใช้งานเกินกำหนดและใกล้ครบ 3 วันทำการจริง รายชื่อรวมคนไม่มีงาน
5. **เวลาและตัวกรอง** — มีตัวกรองทีม/Main KPI ร่วมทุกแท็บ ระบุช่วงข้อมูล วันอ้างอิงความเสี่ยง เวลาอัปเดตไทย และข้อจำกัดย้อนหลัง ตัวกรองแต่ละแท็บมีคำอธิบาย กราฟงานเข้า–เสร็จเป็นจำนวนงาน ไม่ใช่อัตรา Completion และไม่คำนวณเสร็จ/งานเข้าเป็นคะแนน
6. **ใช้งานและตรวจรับ** — รายการการ์ดมีดูทั้งหมด งานแบ่งหน้าละ 50 พร้อมค้นหาและแสดงทั้งหมดเพื่อพิมพ์ ตารางเลื่อนภายในบนมือถือ มี focus/ปุ่ม Escape สำหรับ modal และหน้าพิมพ์แสดงรายละเอียดที่กำลังเปิด

## ขอบเขตข้อมูลและสูตร

- W.Completion = ผลรวมน้ำหนักงานเสร็จ / ผลรวมน้ำหนักงานที่ไม่ยกเลิก × 100
- W.SLA = ผลรวมน้ำหนักงานเสร็จตรงเวลา / ผลรวมน้ำหนักงานเสร็จ × 100
- Performance = ค่าเฉลี่ย W.Completion กับ W.SLA; หากมีเพียงค่าเดียวใช้ค่านั้นตามสูตรเดิม
- Weight ของทะเบียนไม่จำเป็นต้องรวมเป็น 100% และไม่ใช่สัดส่วนภาระงาน
- น้ำหนักจากงานใช้ snapshot ก่อนคอลัมน์เดิมตามลำดับเดียวกับสูตรกลาง หากไม่มีน้ำหนักใช้ 1 ตามพฤติกรรมเดิมพร้อมแจ้งคุณภาพข้อมูล
- งานเสร็จไม่มีวันที่ตรวจ SLA ยังคงพฤติกรรมสูตรเดิม แต่แจ้งความไม่ครบของข้อมูลในชุดที่โหลด
- ข้อมูลเป็นสถานะล่าสุดที่โหลดจาก API การเลือกเดือน/ปีย้อนหลังไม่ใช่การสร้าง snapshot สถานะในอดีต กราฟแสดงเฉพาะงานที่ API ส่งมาในขอบเขตนั้น
- งานค้างรวมงานเริ่มก่อนสิ้นช่วง รวมงานจากปีก่อน งานเสร็จเลือกตามวันปิดในช่วงที่เลือกตามเงื่อนไข backend เดิม
- ค่า Health/Risk adjusted เป็นตัวช่วยติดตามเดิม แยกจาก Performance ไม่เพิ่มเกณฑ์ประเมินหรือสูตรหักคะแนนใหม่

## การทดสอบ

- `npm test` — ชุด logic/reliability เดิม และ Performance model 18 กรณี
- `npm run test:build` — ทดสอบ build/version/assets/clean routes
- `npm run build` — สร้าง dist สำหรับรันจริง (หลัง test:build เพื่อคืน metadata จาก test เป็น build ปกติ)
- `npm run test:performance:browser` — เปิดเว็บ build จริงด้วย Edge headless บน localhost ใช้ข้อมูลจำลองและ API จำลอง ห้ามคำขอเปลี่ยนข้อมูลนอกเหนือจากการเปิด session จำลอง

Browser test ใช้ Playwright ที่ติดตั้งในโครงการ หรือ runtime ที่มีอยู่ใน Codex; กำหนด `PLAYWRIGHT_MODULE_PATH` และ `PLAYWRIGHT_CHANNEL` ได้หากรันนอกเครื่องนี้ ไม่ดาวน์โหลดหรือเพิ่ม dependency ระหว่างทดสอบ

ครอบคลุม 5 แท็บ, nested drilldown, น้ำหนัก override/งานหลายค่า, คนไม่มีงาน, โหมดสว่าง/มืด, มือถือ 390px, print media, Staff/Lead/Manager/Director/Executive/SrManager และ Admin, catalog โหลดไม่ครบ, task API ล้มเหลว, ข้อมูลว่าง, บุคลากร 43 คน, งาน 61 รายการ, pagination/search, การเปลี่ยนปีและหลายเดือน

หลักฐาน QA อยู่ใน `.cache/performance-view-qa/` ได้แก่ `results.json`, ภาพเดสก์ท็อป/มือถือ/โหมดมืด และภาพ print media ใช้ข้อมูลจำลองทั้งหมด

ไม่มีการ deploy, แก้ schema, เปลี่ยนทะเบียน KPI หรือน้ำหนัก/ข้อมูลงานในฐานข้อมูล

## ปรับเป็นสรุปผู้บริหารตามข้อเสนอแนะล่าสุด

หน้าเริ่มต้นแสดงตาราง 6 คอลัมน์: ผู้รับผิดชอบ / Main KPI / น้ำหนักที่ตั้ง / เป้าหมาย / ผลจริง / ผลเทียบเป้า พร้อมยอดคนแบบไม่นับซ้ำ เรียงคนมีงานเกินกำหนดก่อน และค้นหาได้ กราฟ สูตร และแท็บวิเคราะห์เดิมเปิดเฉพาะเมื่อกด “รายละเอียดและการวิเคราะห์” กดชื่อเพื่อดูรายละเอียดบุคคลได้ทันที

ระบบตั้งน้ำหนักและระยะเวลาดำเนินงานได้ แต่ยังไม่มีเกณฑ์ผ่านเชิงอัตรา SLA/Completion จึงแสดง “ยังไม่กำหนด” และ “ยังประเมินไม่ได้” ไม่ใช้ระดับคะแนนเดิมหรือน้ำหนักเป็นเป้าผ่าน ไม่มีการเพิ่มหรือแก้เกณฑ์ประเมินในฐานข้อมูล หากน้ำหนักของ Sub KPI ใน Main เดียวกันต่างกัน แสดงช่วงค่าพร้อมข้อความกำกับ และตรวจค่าแต่ละรายการได้ในรายละเอียด

ทดสอบหน้าสรุปใหม่บนเดสก์ท็อปและมือถือ 390px, การค้นหา, การเปิด/ปิดมุมวิเคราะห์, รายละเอียดรายบุคคล, print media และ regression ของเครื่องมือวิเคราะห์เดิม หลักฐานหน้าสรุป: `.cache/performance-view-qa/executive-brief-desktop.png` และ `executive-brief-mobile.png`
